# 017 VM は取れれば A1、取れなければ E2.1.Micro

- 決めた日: 2026-11-13

## 背景

ADR 003 では、VM を E2.1.Micro（1/8 OCPU・1 GB）にし、A1 を前提にしないと決めた。A1 はリージョンによって空きが無く、作れないことが多いため。この ADR は、ADR 003 のうち VM の種類の部分を置き換える（Docker を VM の上で使うことは変えない）。

E2.1.Micro で基盤の VM を作ってみると、1 GB では次のことが起きた（2026-11-13 実測）。

- 初回の起動（dnf で Docker と OCI CLI を入れる）に約 29 分かかった。スワップは最大 1.5 GB 使った。
- 何もしていない状態（Docker は動いていて、コンテナは無い）で、空きは約 440 MB だった。
- 詳しくは [references/oci-compute-vm.md](../references/oci-compute-vm.md)。

A1 の空きを確かめると、取れることがあった（2026-11-13・実測）。

- 容量の報告（Compute Capacity Report。指定した形の VM をいま作れるかを、何も作らずに問い合わせる API）では、1・2・4 OCPU のどれも `AVAILABLE` だった。
- CLI で 1 OCPU・6 GB を作ると、35 秒で `RUNNING` になった（すぐ消した）。

## 決定

- 基盤の VM は、取れるときは A1（`VM.Standard.A1.Flex`、1 OCPU・6 GB）にする。取れないときは E2.1.Micro にする。
- どちらにするかは、管理者が Terraform の変数で決める。A1 が取れずに作れなかったら、管理者が変数を E2.1.Micro に替えて流し直す。自動で切り替える仕組みは作らない。
- イメージは、そのときの VM の CPU の種類（A1 は arm64、E2.1.Micro は amd64）向けにだけビルドする。VM の CPU の種類を替えたら、載っている全プロジェクトをビルドし直す。
- プロジェクトのイメージは、amd64 と arm64 のどちらでもビルドできるように作ってもらう。

## 理由

- A1 が取れるなら、メモリが 6 倍、CPU が 8 倍になる。1 GB で起きた遅さとメモリ不足の苦労が、ほぼ無くなる。
- A1 は、取れるかがそのときどきで変わる。取れないときに基盤が止まらないよう、E2.1.Micro にも戻れるようにしておく。
- 切り替えは、VM を作り直すときにだけ起きる。頻度が低いので、手で変数を替えれば足りる（ADR 003 と同じく、自動で取り直す仕組みは作らない）。
- 1 OCPU・6 GB は、A1 の無料枠（合計 2 OCPU・12 GB）の半分。残りの半分を別の用途に取っておける。

## 採らなかった案

| 案 | 理由 |
|---|---|
| E2.1.Micro のまま（ADR 003） | 1 GB では、初回の起動が遅く、空きのメモリも少ない。A1 が取れる今は、使わない理由が無い |
| 取れないときに自動で E2.1.Micro に切り替える | 仕組みが増える。切り替えは VM を作り直すときにしか起きない |
| いつも amd64 と arm64 の両方をビルドする（マルチアーキテクチャのイメージ） | VM を替えてもビルドし直さずに済むが、毎回のビルドの時間が増える。VM の CPU の種類を替えるのはまれ |
| A1 を無料枠の全部（2 OCPU・12 GB）にする | 基盤の VM には大きすぎる。無料枠を使い切ると、別の用途で A1 を使ったときに課金される |

## 引き換え

- A1 が取れない時期に VM を作り直すと、E2.1.Micro に替えたうえで、全プロジェクトを amd64 でビルドし直すまで、プロジェクトが動かない。
- A1 には、アイドル回収の条件に「メモリの使用率が 20% 未満」が加わる（CPU・ネットワークの条件と合わせて、7 日の間すべてに当てはまる場合）。6 GB に小さなアプリだけを載せると、当てはまりやすい。PAYG のアカウントが回収の対象になるかは未確認。回収されても、作り直せば戻る（ADR 003 と同じ備え）。出典: [Always Free Resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)（2026-11-13 確認）。
- 手元のマシンが arm64 なら、手元のビルドが A1 と同じ CPU の種類になる。amd64 の VM 向けには、手元で別の CPU の種類のビルド（エミュレーション）が要り、遅い。逆の組み合わせでも同じ。
