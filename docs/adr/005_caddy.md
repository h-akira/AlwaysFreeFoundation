# 005 入口は Caddy

- 決めた日: 2026-11-09 以前（記録: 2026-11-10）

## 背景

1 つの VM（1 つの IP）で、複数のプロジェクトをそれぞれのドメインで HTTPS で受ける必要がある。証明書は Let's Encrypt で取る。

## 決定

- Caddy を 1 つ置き、ドメイン名でプロジェクトに振り分ける。パスでは分けない。
- 80 番は常に全体に開ける。

## 理由

- Caddy は証明書の取得と更新を自動で行い、プロジェクトを足しても設定が数行増えるだけで済む。
- IP が 1 つでも、ブラウザが送る名前（TLS の SNI と HTTP の Host ヘッダ）で振り分けられる。
- パスで分けると、各アプリがベースのパスに対応しないといけない。
- 80 番は、Let's Encrypt が証明書を出す前の確認（HTTP-01）と、HTTP から HTTPS への転送に使う。80 番を開けておけば、443 番を決めた IP からだけにしても、証明書の取得と更新は止まらない。

## 引き換え

- VM を作り直すと、証明書は Caddy が取り直す。Let's Encrypt には、同じ名前の組の証明書を 7 日に 5 枚までという発行の制限がある（[Rate Limits](https://letsencrypt.org/docs/rate-limits/)）。本番では作り直しはまれなので気にしない。開発中は作り直しを控えめにする。

## 採らなかった案

| 案 | 理由 |
|---|---|
| nginx + certbot | 証明書を取る手順が別に要り、プロジェクトを足すたびに設定の差し替えが要る |
| Traefik | コンテナのラベルで自動設定でき便利だが、動きが見えにくい |
| OCI Load Balancer + OCI Certificates | Let's Encrypt の証明書を自動で更新する仕組みが別に要り、部品が増える |
