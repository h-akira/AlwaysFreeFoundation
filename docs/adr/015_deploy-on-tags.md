# 015 デプロイの合図はタグの push。基盤のコードもタグで版を決める

- 決めた日: 2026-11-10
- 状態: 採用

## 背景

最初は、各プロジェクトのリポジトリの `release` ブランチへの push でデプロイすることにしていた。基盤のコードは、VM がタグで固定して取ることにしていた。

## 決定

- 各プロジェクトのリポジトリにタグ（例: `v1.2.3`）を push すると、そのプロジェクトをビルドしてデプロイする。デプロイした版の名前（`AFP_TAG`）は、タグの名前そのもの。
- 基盤のコードも、タグで版を決めて VM に届ける。どのタグを使うかを Object Storage に置き、VM の `afp` はそのタグのコードを公開リポジトリから取って入れ替える。

## 理由

- デプロイの合図を、ふだんの push と分けて明示的にする。`main` への push のたびにデプロイすると、手元で確かめる前に本番に届く。
- タグなら、本番に出した版に名前が付き、どのコミットかが後から分かる。戻すときも版の名前で指せる。
- 基盤のコードの版を VM の作成時の設定（user_data）に入れると、版を上げるたびに VM が作り直される。Object Storage に置けば、VM を作り直さずに上げられる。

## 採らなかった案

| 案 | 理由 |
|---|---|
| `release` などのブランチへの push | 合図にはなるが、出した版に名前が残らない |
| 基盤のコードを、手元の HEAD の tar として Object Storage に置く | GitHub への push とタグ打ちが要らず開発中は速いが、版の管理がタグほどはっきりしない |
