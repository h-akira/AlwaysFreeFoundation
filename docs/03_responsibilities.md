# 03 役割と責任

[01](01_purpose.md) §4 の方針どおり、基盤の管理者とプロジェクトの管理者の受け持ちを分ける。ここで決めた境目が、基盤とプロジェクトの約束になる。

## 1. 二つの役割

| 役割 | 受け持つもの |
|---|---|
| **基盤の管理者**（以下「基盤」） | 共有のもの。VM・入口（Caddy・証明書）・MySQL HeatWave の DB システム・Vault の仕組み・DevOps の共通部分・Object Storage・レジストリ・ネットワーク・IAM・費用（[02](02_architecture.md) §3） |
| **プロジェクトの管理者**（以下「プロジェクト」） | 自分のプロジェクトの中のもの。アプリ・自分の DB の中身・自分のシークレットの値・自分のドメインと DNS・自分のアプリの監視 |

同じ人が両方を担ってもよい。それでも分けるのは次の理由から。

- **境目が約束になる**。どちらが何を渡すかが決まっていれば、基盤を変えてもプロジェクトは変わらず、プロジェクトを足しても基盤は変わらない。
- **基盤は公開、プロジェクトは非公開にできる**。基盤はプロジェクトの中身を知らない。
- 障害のとき、どこを見ればよいかがすぐ分かる。

原則: **基盤は仕組みを用意し、プロジェクトはそれを使う。基盤はプロジェクトの中身（アプリの正しさ・データ）に責任を持たない。プロジェクトは共有のものを直接触らない。**

## 2. 責任の表

| 対象 | 基盤 | プロジェクト |
|---|---|---|
| VM（作成・作り直し・OS の更新） | ◎ | — |
| 入口（Caddy・証明書・振り分け） | ◎ | ドメイン名を一覧に書く |
| 443 を公開するか（全体に開くか、決めた IP からだけか） | ◎ 切り替える（VM ごとに一律） | 公開が要るかを基盤に伝える。公開されたときは自分のログインで守る |
| ドメインの取得と DNS | VM の IP を知らせる。IP が変わるときは前もって知らせる | ◎ A レコードを VM の IP に向ける。DNS のサービスは問わない |
| ビルドとデプロイの仕組み（DevOps の共通部分・`afp deploy`・失敗時の自動の戻し） | ◎ | 約束のファイルを書き、自分のリポジトリの `release` ブランチに push する |
| アプリの動作・不具合 | — | ◎ |
| ログインと、その回数制限 | — | ◎ アプリの中で行う。基盤の入口は持たない |
| HeatWave の DB システム（稼働・定期的に触ること・接続数の全体の上限） | ◎ | — |
| プロジェクトの DB とユーザの作成 | ◎ | — |
| DB の中身（テーブル・マイグレーション・データの正しさ） | — | ◎ |
| MySQL の版が上がったとき | 手元用の版の指定を上げ、知らせる | 自分のアプリをテストし直す |
| DB のバックアップ | ◎ 仕組みを動かす | — |
| DB の復元 | 道具を用意する | 戻すかどうか・どの時点に戻すかを決めて実行する |
| シークレットの仕組み（Vault・名前の決まり・環境変数への差し込み） | ◎ | — |
| シークレットの値 | 生成できるものは Vault が生成する | 外から持ってくる値（外部の API キーなど）を入れる |
| 基盤の監視（VM・HeatWave が動いているか） | ◎ | — |
| アプリの監視（自分のアプリが使えるか） | — | ◎ 基盤は道具も見本も用意しない |
| 費用 | ◎ 予算とアラート | メモリの上限などの約束を守る |

- 入口や証明書が壊れたことは、基盤の監視では分からない。各プロジェクトのアプリの監視で気付く。
- 基盤の操作（デプロイ・DB の削除・復元）を Web で受け付けることはしない。入口が増え、壊されたときの影響が全プロジェクトに及ぶため。基盤の操作は ssh で行う。

## 3. 境目

基盤とプロジェクトがやり取りするのは、次のものだけ。

| 向き | もの |
|---|---|
| プロジェクト → 基盤 | プロジェクトの一覧の1項目（名前・リポジトリ・ドメイン・載せる VM・シークレットの名前）。基盤の非公開の設定に書く |
| プロジェクト → 基盤 | 約束のファイル（コンテナの構成・ビルドの手順）。プロジェクトのリポジトリに置く |
| プロジェクト → 基盤 | 自分のリポジトリの `release` ブランチへの push |
| 基盤 → プロジェクト | VM の IP（A レコードの向け先）と、443 を公開しているか |
| 基盤 → プロジェクト | 環境変数（DB の接続先・ドメイン・プロジェクト名・シークレット）。デプロイのたびに渡す |
| 基盤 → プロジェクト | 本番の MySQL の版と設定（手元の開発用）。基盤のリポジトリに置く |
| 基盤 → プロジェクト | デプロイの成否、MySQL の版が上がったことの知らせ |
| 基盤 → プロジェクト | 道具（手元からのデプロイ・戻し・復元・ログの確認）。基盤のリポジトリに置く |
