# 013 スタックを、destroy で消せるかどうかで 2 つに分ける

- 決めた日: 2026-11-10

## 背景

最初は Terraform のスタックを 1 つにしていた。2026-11-09 に `destroy` すると、コンパートメント以外はすべて消えたが、最後のコンパートメントで失敗した。Vault は消してもすぐには消えず、削除待ち（7〜30 日）の間コンパートメントの中に残り、中身の残るコンパートメントは消せないため（[references/oci-vault.md](../references/oci-vault.md)）。

## 決定

- スタックを 2 つにする。
  - base: Terraform の destroy で消せないものだけ。コンパートメント・Vault・Vault の鍵。
  - 本体: それ以外のすべて。消えると困るもの（ダンプを置くバケット・予約済みの IP）も、destroy で消せるなら本体に置く。本体の destroy の前にバケットを空にする。
- 本体は、base の資源を名前で探す。スタックの間で値を受け渡す仕組みは作らない。
- 本体のシークレットの名前には、作るたびに変わる接尾辞を付ける。

## 理由

- base に置く理由は「destroy で消せない」の一点に絞る。消えると困るかどうかは、base に移す理由にしない（守り方は ADR 012 の引き換え）。そうすれば、base は小さく、ほとんど変わらない。
- 名前で探せば、2 つのスタックの間をつなぐ仕組みが要らない。
- 消したシークレットも削除待ち（既定 30 日）として base の Vault に残る。接尾辞が無いと、作り直したときに名前がぶつかるおそれがある。

## 採らなかった案

| 案 | 理由 |
|---|---|
| スタックを 1 つのまま | destroy が毎回最後で失敗する。作るたびに、削除待ちの Vault が 1 つずつ溜まる |
| コンパートメントだけを消せなくする（`enable_delete = false`） | destroy すると、コンパートメントは Terraform の管理から外れて OCI に残る。作り直すと名前がぶつかるので、取り込み直す手間が毎回かかる |
| base を Terraform の外（スクリプト）で作る | 何度流しても同じ結果になるように、自分で書く必要がある |
| めったに変えないものと、よく変えるもの（プロジェクトの追加）で分ける | 変える頻度は、消せるかどうかほど分ける理由にならない |
| バケット・予約済みの IP も base に置く | 消せないわけではない。中身を消せば消せる |
| シークレットも base に置く | 本体の DB と寿命がずれる |
